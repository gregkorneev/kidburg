## Что не удалось или не проверено

* **FPS при показанной панели браузера.** Когда панель встроенного браузера скрыта, страницы идут как фоновые (1 к/с). Значения FPS 60 получены, пока панель была видна; цифры 1–17 FPS в других моментах — артефакт окружения, а не производительность игры.
* Два клиента одновременно получили 60 FPS только после поочерёдного вывода вкладок вперёд: в одной панели реально отрисовывается одна вкладка. Два настоящих окна (Chrome в разных окнах) не проверялись — расширение Claude in Chrome не было подключено. Проверка двух сессий серверной частью (разные `sid`, разные игроки, разные локации) выполнена и в автотестах.
* Playwright и Chrome DevTools MCP в проекте не установлены (зависимости не добавлялись); использован встроенный браузер.
* Не проверено: ширина 360 px, журнал «Показать ещё» (записей было мало), переподключение SSE с сохранением сессии, возврат дальнего клиента к объектам в чанке (покрыто `ws-dynamic.test.js`, но не в браузере), доступ с другого компьютера локальной сети (`ADMIN_ALLOW_REMOTE=1`; покрыто автотестом, без второго устройства).
* Отклонение по лимиту кеша `cache_budget` в браузере не воспроизведено: раньше срабатывали `limit_chunk` (30 на чанк) и сжатие набора чанков; отдельный тест на `cache_budget` есть в `tests/world-objects.test.js`.
* Реальный диалог игрока с агентом через игровой чат не проводился (Маруся живёт в станции пожарной части); проверялся тот же путь `reply()` через «Спросить агента».

## Происшествие во время проверки

Первый запуск сервера для браузерной проверки через `scripts/start.mjs` **не читает `DB_PATH`** (путь к базе берётся только в `server/index.js` при запуске как главного модуля), поэтому сервер открыл настоящую `data/city.db`. Что произошло: добавились пустые новые таблицы (безопасная миграция), созданы два тестовых игрока «Аня» и «Борис» (id 4, 5) и две записи журнала. Я удалил именно эти строки (игроков 4 и 5 с их состоянием и сессией, записи журнала), счётчик id возвращён к 3; игроки `test1`, `GREG`, `1GREG` не тронуты. Новые пустые таблицы остались (они нужны коду). Как обычно при любом запуске сервера, `server/index.js` при старте очищает все игровые сессии (`clearSessions`) — это существующее поведение. Дальше использовался изолированный `run-e2e.mjs`. Рекомендация: для безопасных проверок запускать сервер напрямую через `startServer({ dbPath })`; `npm run verify` по-прежнему стартует сервер на настоящей БД (так было до этой работы).
