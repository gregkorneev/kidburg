# Настройки ИИ-агентов

Базовые персоны (`server/agents/personas/*.json`) не меняются. Правки админа хранятся в таблице `agent_settings`
как переопределения поверх персоны и применяются **без перезапуска** сервера.

## Поля

| Поле | Смысл |
|---|---|
| `enabled` | агент доступен; выключен → NPC вежливо сообщает о недоступности |
| `displayName` | имя в разговоре (подпись над NPC в мире не меняется) |
| `personalityNotes`, `speechStyle` | дополнения к личности и манере речи (≤ лимитов, дополняют, не заменяют) |
| `topics`, `topicMode` | предпочитаемые темы; `open` / `focused` (возвращать разговор к профессии) |
| `verbosity` | кратко / обычно / подробнее (длина и лимит токенов) |
| `friendliness` (1–5), `initiative` (0–3) | тон и инициативность |
| `temperature` | 0,1–1 или пусто (по умолчанию сервера) |
| `introduceSelf`, `reactToTaskProgress` | самопредставление, учёт хода задания |

## Приоритет

1. Правила системы (безопасность, формат, возраст аудитории, офлайн-логика) — всегда первыми в промпте.
2. Базовая персона.
3. Настройки админа — отдельным блоком **после** персоны.
4. Текущий разговор и память игрока.

Настройки не могут отменить правила: фильтр отклоняет явные попытки («игнорируй правила», «покажи системный промпт»),
а порядок блоков не позволяет им вытеснить системные.

## Проверка на настоящей модели

`POST /api/admin/agents/:id/test` отправляет реплику в Ollama с **несохранёнными** настройками из формы. Запрос
эфемерный: память игроков и история разговоров не читаются и не пишутся (служебный `userId 0`). Если Ollama не запущена
или модель не задана, панель честно показывает состояние (`not_configured`, `unavailable`, `model_missing`) и не
подставляет выдуманный ответ.

## Действия

Сохранить (валидация по полям, ошибки показываются у поля), отменить несохранённые правки, сбросить к базовой персоне
(`DELETE`/`reset`). Каждое действие попадает в журнал; пароли и токены туда не записываются.
