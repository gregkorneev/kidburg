# Редактор мира

## Модель

Динамический слой — объекты, которые админ добавил поверх статического мира (`generated/`). Он хранится в SQLite
(`world_objects`), статические файлы чанков никогда не изменяются. Источник правды — сервер: клиент получает объекты
сообщениями `dyn_snapshot` / `dyn_upsert` / `dyn_remove` и ничего не решает сам.

Объект: `{ id: "o_<10 hex>", type, x, z, ry, scale, params, rev }`. `rev` — ревизия объекта; на сервере ещё есть глобальная
монотонная ревизия мира.

## Разрешённые типы

`tree` (вид: лиственное/ель/берёза), `bush`, `bench`, `lamp`, `rock`, `flowerbed`, `crate`, `sign` (надпись ≤ 28 символов).
Описание, радиусы, границы масштаба и коллайдеры — `shared/world-objects.js`; геометрия — `client/engine/dynamic-types.js`
(процедурная, тот же конструктор, что у остальных префабов).

## Проверка размещения (на сервере)

Объект отклоняется с понятным текстом, если он:
* вне мира или ближе 4 м к краю;
* пересекает здания, их двери и подходы, маршруты NPC, дорожки, площадь/точку появления, статичные объекты, NPC;
* ближе 0,2 м к другому динамическому объекту;
* превышает лимиты (150 всего, 30 на чанк);
* нарушает **лимит кеша клиента**: для каждой области 3×3 чанка сумма байт (файлы + динамика) ≤ 10% всего мира.

`POST /api/admin/world/validate` проверяет заранее (редактор подсвечивает допустимое/недопустимое место).

## Синхронизация

* Игрок получает объекты только для чанков из своего кеша: после `chunk_load` — `dyn_snapshot`; `chunk_unload` убирает их у клиента.
* Любое изменение уходит `dyn_upsert`/`dyn_remove` только тем, у кого чанк загружен. Игрок, который был вдалеке, получит
  актуальное состояние при следующей загрузке чанка.
* Устаревшие сообщения отбрасываются по `rev`; повторное «воскрешение» удалённого невозможно.
* Размер чанка для кеша учитывает динамические объекты (`wrapWorld`), поэтому лимит 10% не обходится.

## Клиент

`client/engine/dynamic-objects.js`: меши через общий пул (геометрии `dyn-geo:*` и материал `dyn-mat` со счётчиком ссылок),
коллайдеры объединяются со статическими (`worldView` в `app.js`) — игрок и камера обходят новые объекты. Удаление, выгрузка
чанка и сброс мира освобождают геометрии, материалы и подписи табличек из DOM (тест: пул после `clear()` пуст).

## Откат и журнал

Каждое действие пишется в `admin_audit_log` с состоянием «до/после». `POST /api/admin/world/undo` откатывает последнее
изменение мира (создание → удаление, удаление → восстановление, перенос → возврат); при расхождении ревизии отвечает
конфликтом, не портя состояние. Игроки получают результат откатa тем же способом.

## Перезапуск

Объекты восстанавливаются из SQLite при старте; глобальная ревизия хранится в `world_meta`.
