## Подтверждённые дефекты

### P2 — Новые игроки появляются в одной точке, удалённый аватар перекрывает камеру

- **Где:** сервер использует `db.getPlayerState(user.id) ?? SPAWN` в [server/net/game.js](../server/net/game.js#L171); общий `SPAWN` фиксирован в [shared/constants.js](../shared/constants.js#L19). Удалённая модель создаётся в клиентской сцене рядом с локальным игроком.
- **Как воспроизвести:** открыть игру в двух отдельных браузерных клиентах; каждый раз ввести новое имя и войти в один код комнаты; до перемещения открыть снимок обоих клиентов.
- **Ожидаемое поведение:** при входе второго игрока его аватар не должен закрывать камеру и основную часть игрового экрана первого игрока.
- **Фактическое поведение:** оба новых игрока получают координаты одной точки `SPAWN`. У первого клиента модель второго появляется вплотную к камере и занимает большую часть изображения. На снимке второго клиента наблюдается такое же перекрытие. После перемещения первого игрока изображение освобождается.
- **Причина:** для новых профилей сервер выдаёт одинаковую точку; начальная расстановка не раздвигает игроков и клиент не исключает аватар, находящийся внутри камеры.
- **Предлагаемое исправление:** выдавать новым подключениям ближайшие свободные стартовые позиции либо применять серверную расстановку с минимальной дистанцией между игроками; дополнительно обеспечить минимальную дистанцию камеры до чужой модели.
- **Подтверждение:** [клиент 1 до перемещения](../output/playwright/multiplayer-client-1.png), [клиент 2 до перемещения](../output/playwright/multiplayer-client-2.png), [клиент 1 после перемещения](../output/playwright/multiplayer-after-move.png).
- **Приоритет:** P2 — блокирует обзор при старте многопользовательской сессии, но игрок может исправить ситуацию движением.

### P2 — `npm run check:offline` всегда завершается ошибкой

- **Где:** [package.json](../package.json#L17) запускает отсутствующий `scripts/check-offline.mjs`.
- **Как воспроизвести:** выполнить `npm run check:offline`.
- **Ожидаемое поведение:** отдельная проверка клиентских файлов на запрещённые внешние URL завершается результатом проверки.
- **Фактическое поведение:** Node.js завершается с `MODULE_NOT_FOUND: Cannot find module '.../scripts/check-offline.mjs'`.
- **Причина:** npm-скрипт объявлен, но целевого файла в репозитории нет.
- **Предлагаемое исправление:** восстановить проверочный скрипт либо убрать команду из `package.json` и документации; ограничение офлайн-поставки должно оставаться проверяемым.
- **Подтверждение:** фактический запуск команды во время аудита; автоматический набор отдельно проверяет отсутствие внешних URL только в покрываемом им коде.
- **Приоритет:** P2 — ломает объявленную проверку одного из главных требований проекта.

### P3 — Браузер запрашивает отсутствующий `/favicon.ico`

- **Где:** корневая страница [client/index.html](../client/index.html#L1) не задаёт favicon; файла `/favicon.ico` нет.
- **Как воспроизвести:** открыть новую сессию `http://127.0.0.1:3000/` и посмотреть сообщения консоли/сетевые запросы браузера.
- **Ожидаемое поведение:** локальный favicon отвечает 200 либо страница не порождает запрос к отсутствующему ресурсу.
- **Фактическое поведение:** Chromium регистрирует `Failed to load resource: the server responded with a status of 404 (Not Found) @ http://127.0.0.1:3000/favicon.ico`.
- **Причина:** браузер запрашивает стандартный путь, а локального файла или явной ссылки нет.
- **Предлагаемое исправление:** добавить локальную иконку и ссылку на неё либо отключить запрос корректным локальным способом.
- **Подтверждение:** консоль Playwright на первой загрузке обоих браузерных клиентов.
- **Приоритет:** P3 — не влияет на запуск игры, но оставляет сетевую ошибку в чистой консоли.

### P3 — Firefighter preview вызывает удалённые из Three.js API

- **Где:** [client/stations/firefighter/scene.js](../client/stations/firefighter/scene.js#L73) задаёт `THREE.PCFSoftShadowMap`; строка 247 создаёт `THREE.Clock`.
- **Как воспроизвести:** открыть `/firefighter-preview.html` и проверить консоль Chromium.
- **Ожидаемое поведение:** рендерер использует актуальные API Three.js без предупреждений и без неявной замены настройки теней.
- **Фактическое поведение:** консоль выдаёт `THREE.Clock: This module has been deprecated. Please use THREE.Timer instead.` и `THREE.WebGLShadowMap: PCFSoftShadowMap has been removed. Using PCFShadowMap instead.`
- **Причина:** код использует API, удалённый или объявленный устаревшим в используемой версии Three.js.
- **Предлагаемое исправление:** заменить устаревший таймер и выбрать поддерживаемый тип карты теней после визуальной проверки.
- **Подтверждение:** две воспроизводимые записи уровня warning при открытии preview; ошибок рендеринга не зарегистрировано.
- **Приоритет:** P3 — сейчас Three.js продолжает рендерить, но настройка теней молча заменяется.

## Ограничения аудита

- Отдельного Chrome DevTools MCP в доступных инструментах не оказалось. Для реального Chromium использован установленный Playwright CLI, его консоль/сеть и CDP `Performance` через Playwright.
- Сетевой прогон выполнялся двумя независимыми браузерными клиентами на одном серверном компьютере; физический LAN-клиент и нестабильная Wi-Fi-сеть не проверялись.
- Производительность замерена на Apple M4 Pro, поэтому значения FPS не прогнозируют скорость школьного или слабого ноутбука.
- Проверена основная городская сцена и интерактивная пожарная станция. Другие станции проверяются в существующих тестах конструкций; их полные браузерные игровые циклы в этом прогоне не выполнялись.
- Полное прохождение четырёх окон и этапа с манекеном вручную не завершалось. Их серверная логика имеет unit/integration coverage в текущем наборе, но это не заменяет браузерный end-to-end прогон.
- Графическое освобождение проверялось по `renderer.info.memory` для удалённого игрока. Метрики памяти GPU-процесса Chromium отдельным системным профайлером не снимались.
- Статический кандидат по обработке исключений SQLite в WebSocket HELLO не воспроизводился отказом хранилища и потому не классифицирован как подтверждённый дефект.

## Итог первичного аудита до исправлений

Подтверждённый игровой дефект — совпадающий старт игроков с перекрытием камеры. Изменения в исходном коде, тестах, коммиты и отправка в удалённый репозиторий не выполнялись. Этот отчёт и скриншоты оставлены локально.
