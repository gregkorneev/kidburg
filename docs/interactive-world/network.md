# Сетевой протокол

Протокол v1 (MessagePack), схемы в `shared/protocol.js`. Новые сообщения — добавления, старые клиенты их игнорируют.

| Направление | Сообщение | Содержимое |
|---|---|---|
| C2S | `interact` | `{id, action: take\|place\|drop\|kick, seq}` — только эти поля, лишние отбрасываются |
| S2C | `interact_result` | `{seq, ok, code, message?}`; коды: ok, unknown, too_far, busy, hands_full, not_holding, blocked, rate_limit, cooldown |
| S2C | `prop_snapshot` | полный список предметов (при входе/переподключении) |
| S2C | `prop_state` | одно изменение предмета (взятие, постановка, возврат) |
| S2C | `ball_snapshot` | `{tick, list: [[id,x,y,z,vx,vy,vz,flags]…]}` |
| S2C | `ball_event` | `{kind: kick\|reset, id, …}` |
| C2S/S2C | `mech_set` / `mech_state` / `mech_snapshot` | двери (как у ворот), с `progress` и `ageMs` |

## Защита

Неавторизованный клиент и сообщения с неверной схемой отклоняются; лимит 8 `interact`/с на соединение; дальность и направление проверяет сервер по собственной позиции игрока; все числа конечны (NaN отбрасывается на входе и в физике).

## Переподключение

Новое соединение получает `prop_snapshot`, `mech_snapshot` и актуальный `ball_snapshot`; клиентский счётчик тиков сбрасывается (`resetClock`). Предмет, который держал отключившийся игрок, сервер уже вернул.

## Нагрузка

Мячи рассылаются только игрокам рядом с полем и только при изменениях; предметы — событиями. В покое трафика мячей нет.
