# Как получить такой дизайн: практическое руководство

Руководство описывает, как в Kidburg делается стилизованная low-poly/cartoon графика уровня площади и пожарной части:
от идеи до проверки в браузере. Все примеры — реальный код проекта. Без внешних ассетов, шрифтов и CDN: только процедурная
геометрия, вершинные цвета и canvas-текстуры.

Связанные документы: `plaza-overhaul.md` (что сделано и замеры), `art-direction.md` (общая арт-дирекция).

---

## 1. Принципы стиля

1. **Простые формы с мягкими фасками.** Любая коробка — скруглённая (`radius 0.05–0.1`), острые рёбра выдают «компьютерность».
2. **Цвет в вершинах, а не в текстурах.** Один материал на префаб, цвет каждой детали записан в вершины. Это даёт один draw call на префаб и работает с `InstancedMesh`.
3. **Общая палитра** (`client/engine/art/palette.js`): тёплый солнечный свет, прохладные тени, приглушённые фоны; яркие цвета — только для акцентов (маршруты, вывески, интерактивные предметы).
4. **Запечённое затемнение.** Низ стен темнее (ambient occlusion в вершинах), нижние грани темнее на ×0.74–0.8, под карнизами — полосы. Объём читается без динамических теней.
5. **Мелкие детали рассказывают профессию.** Пекарня — навесы с бахромой и батон; музыкальная школа — «клавиши» и скрипичный ключ; радио — мачта с маячком.
6. **Иерархия силуэтов.** Крупное (здание, фонтан) → среднее (пилоны, деревья, фонари) → мелкое (цветы, камни). Каждый уровень виден с своей дистанции.
7. **Разброс яркости.** Каждая деталь получает случайный сдвиг яркости ±3.5% (`tint`) — эффект ручной покраски вместо плоской заливки.

## 2. Рабочий процесс (по шагам)

1. **Зафиксируйте ограничения** — размеры, позиции, коллайдеры, интерактивные точки (например, дверь пожарной части на локальном x = 7.72). Дизайн вписывается в них, а не наоборот.
2. **Нарисуйте план** в виде чистых данных (как `plaza-plan.js`): где маршруты, газоны, мебель. Никакого three.js — только числа, чтобы это можно было тестировать.
3. **Соберите геометрию** через `createPrefabKit()` (раздел 3) — от крупных объёмов к мелким деталям.
4. **Добавьте «живое»** отдельным слоем (`city-decor.js`): вывески, вода, ветер. Статика остаётся в одном меше.
5. **Подключите** через `prefabs.js` / `chunks.js` (раздел 8).
6. **Напишите тесты** (раздел 10) — до визуальной проверки, чтобы не искать ошибки глазами.
7. **Соберите и посмотрите** в браузере с одинаковыми ракурсами до/после (раздел 9).
8. **Измерьте** draw calls и треугольники (раздел 11), при необходимости упростите.

## 3. Конструктор префабов `art/prefab-kit.js`

```js
import { createPrefabKit } from './art/prefab-kit.js';

const k = createPrefabKit({ seed: 12, tint: 0.035 });
k.slab(17.6, 0.45, 13.4, 0, 0, 0, 0xdcd0b0, { r: 0.1 });   // коробка, стоящая на y=0
k.box(w, h, d, x, y, z, color, { r: 0.06, ry: angle });      // коробка по центру (x,y,z)
k.cyl(rTop, rBottom, h, segments, x, y, z, color);
k.sphere(r, x, y, z, color, { s: [1, 0.5, 1], w: 8, h: 6 }); // сплюснутая сфера = куст, булка, купол
k.lathe([[r, y], ...], 24, x, y, z, color, { phiStart, phiLength }); // чаши, бордюры, кольца
k.flatShape([[x, z], ...], y, 0.016, color);                 // плоский узор на земле
k.tube([[x,y,z], ...], 0.05, color);                         // антенны, буквы, дуги
const geometry = k.build({ groundAO: { height: 2, strength: 0.3 }, bands: [{ y0: 8.7, y1: 9.1, strength: 0.15 }] });
```

Готовые составные части: `gableRoof` (черепичная крыша), `window` (рама, подоконник, ставни, ящик с цветами),
`door` (двустворчатая дверь со ступенями), `awning` (полосатый навес с бахромой), `bench`.

Правила:

* **`at([x,y,z], rotY, fn)`** — локальная система координат: окна и двери рисуются «лицом» к +Z и ставятся на любую стену.
* **Лицо здания смотрит в +Z.** Поворот инстанса задаёт мир.
* `tinted: false` — для деталей, которым нужен точный цвет (стекло, блики, лампы).
* Мелкие детали (минимальный размер < 0.14 м) не скругляются автоматически — фаска на них не видна, а треугольники дороги.
* Общие геометрии `roundedBox` кешируются; кит копирует их, поэтому правка не ломает кеш.
* Геометрия получается **без индекса**, только `position/normal/color` — её можно объединять и выгружать в чанках.
* Ничего не должно уходить ниже `y = 0` заметно: тесты зданий проверяют `boundingBox.min.y ≥ 0` (цилиндр с низом ровно в 0 даёт `-3e-10` — поднимайте на 0.001–0.005).

### Рецепт здания

1. Цоколь (`slab`), корпус, цветной пояс внизу (`peach`/`brick`/`blue`), угловые пилястры, карниз.
2. Крыша (`gableRoof`) + труба/слуховое окно/купол.
3. Окна рядами: нижний ряд — витрины крупнее, верхний — с ставнями и цветами.
4. Вход: `door` + козырёк/навес + светильники + порожек.
5. Эмблема профессии над входом (батон, скрипичный ключ из `tube`, дуги сигнала).
6. Уличные детали: столик, корзины, меловая доска, бочка, урна, лавки.
7. `build()` с `groundAO` ≈ 0.3 на высоту 2 м и полосой под карнизом.
8. Вывеску в геометрию **не** кладите — она в `*_SIGNS` и рисуется отдельной табличкой с текстом.

Проверьте: размеры совпадают с `collider` в `prefabs.js`, нет вылета за габариты более чем на пару метров, число треугольников разумно (у зданий 11–18k, цветочная лавка 30k — предел).

## 4. Растения и мебель `art/flora.js`

Все функции принимают кит и координаты и добавляют детали:

| Функция | Что даёт |
|---|---|
| `roundTree`, `pineTree`, `birchTree` | три силуэта: шарами, ярусами, светлый ствол |
| `bush`, `flower` | куст из 4 шаров, цветок из 5 лепестков |
| `roundBed`, `planterBox` | клумбы (в площади используются пустые, растения — в декоре) |
| `lampPost`, `bin`, `signpost`, `infoStand`, `picketFence`, `rock` | мебель и мелочь |
| `TREE_BUILDERS`, `buildBenchPrefab`, `buildLampPrefab` | готовые префабы для мира |

Приёмы: крона дерева — 5 сфер разного размера и оттенка; цветок — отдельный цвет лепестков (`tinted: false`), листья
всегда из `FLORA_COLORS.leaf`. Растения на растоянии выглядят как «пятна» — не жалейте оттенков (4 зелёных, а не 1).

## 5. Площадь: как строить композицию

* **Маршруты.** Для каждого здания: линия от центра к середине фасада. Все остальное расставляется *между* маршрутами по углам секторов.
* **Газоны.** Контур — дуги и прямые, параллельные осям маршрутов на `inset = 2.35 м`; полосы скашивания — пять колец чередующихся зелёных (`lawnOutline` + `flatShape`). Бордюр — ряд плоских боксов вдоль контура.
* **Брусчатка.** Кольцевые плитки (`ringTiles`): верхняя грань на `y=0.1`, подложка — на `0.088`; шов — это просто просвечивающая подложка. Боковых граней нет → в 3–4 раза меньше треугольников. Для разных зон (дно фонтана, площадка, маршруты, внешнее кольцо) подставляется функция выбора цвета.
* **Узоры.** Звезда-компас — цвет плитки по формуле `r < 0.8 + 1.5·|cos(4a)|⁴`; шевроны — `flatShape` над плиткой (на 0.016 выше); медальоны — стопка тонких цилиндров разных цветов.
* **Фонтан.** Центральная площадка (точка появления игроков) → кольцо воды → низкий бортик с разрывами у маршрутов (**каменные броды**) → пилоны по секторам. Вода и струи — живой слой.
* **Расстановка с проверкой.** Все позиции вычисляются от углов секторов и проверяются функциями `distanceToRoutes`, `distanceToBuildings`, `isClear`, `onLawn`. Это превращает «на глаз» в проверяемое утверждение.

## 6. Живой слой `city-decor.js`

Хук `prefab.decorate({group, instance, quality})` создаёт объекты рядом с инстансом и возвращает
`{update(dt, elapsed), setQuality(level), dispose()}`.

* **Вывески** — `createSignDecor(signs)`: рамка + табличка с canvas-текстом (`labels.js`), положение задаётся в локальных координатах здания и поворачивается вместе с инстансом.
* **Вода** — `ShaderMaterial` на кольце: сумма четырёх синусов даёт волны и блики, у берега цвет смешивается в «пену». В конце фрагментного шейдера обязательно `#include <tonemapping_fragment>` и `#include <colorspace_fragment>`, иначе цвет будет выбиваться из сцены.
* **Струи** — `THREE.Points`, где траектория считается в вершинном шейдере: `p = mix(start, land, u); p.y += 4·apex·u·(1−u)`, `u = fract(time·speed + phase)`. Нужен фиктивный атрибут `position` (число вершин) и `frustumCulled = false`. Порядок частиц «по одной от каждой струи» позволяет резать качество через `drawRange`.
* **Ветер** — `art/wind.js`: `swayMaterial(strength)` добавляет в вершинный шейдер сдвиг `sin(t·1.5 + phase)·position.y·strength`. Фаза берётся из положения экземпляра, поэтому растения качаются не синхронно. Сила: цветы 0.16, кусты 0.05, деревья 0.014. Время — глобальное `updateWind(elapsed)`.
* **Подъезды** — плитки в декартовых координатах вдоль оси маршрута (4 колонки по 1 м), крайние тёмные, у двери — цвет здания.
* **Освобождение.** `disposeDecor(root)` освобождает всё, кроме объектов с `userData.shared` (общие геометрии растений и материалы ветра).

## 7. Свет, тени и качество

* Свет — `applyStylizedLook` (`art/lighting.js`): ACES, полусфера 1.45, солнце 2.7, контровой 0.55, туман и небо. Все сцены берут его, чтобы город и пожарная часть выглядели единым миром.
* Тени: `renderer.shadowMap.enabled = true`, `shadowExtent: 30` — карта следует за игроком с привязкой к метровой сетке (тени не «плывут»). Меши префабов: `castShadow = true`, земля и подъезды — `receiveShadow`.
* Уровни `art/quality.js`: `low` (без теней, pixelRatio 1, detail 0.35), `medium` (1024, 1.5, 0.7), `high` (2048, 2, 1). Выбор — `?quality=low|medium|high` или `localStorage`. В коде: `stylized.setQuality(level); world.setQuality(level)`.
* Правило: **любая новая «фича красоты» обязана реагировать на уровень** — число частиц, экземпляров, текстурная детализация.

## 8. Подключение в игру

1. Построитель геометрии → `PREFABS[id].build` в `prefabs.js`; `vertexColors: true` (материал `MeshStandardMaterial`, один на ID).
2. Нужны варианты (деревья разной формы, дорожки разных размеров) → `variantOf(x, z)` и `buildVariant(variant)`; формат чанка не меняется, вариант выбирается по положению.
3. Нужен живой слой → `decorate`.
4. `chunks.js`: группировка инстансов по `id:variant` (один `InstancedMesh` на вариант), запуск `decorate`, `update`, `setQuality`, `dispose` вместе с чанком.
5. Ничего не добавляйте «глобально» в сцену — всё привязано к чанку и освобождается с ним (лимит кеша 10% и стриминг сохраняются).

## 9. Визуальная проверка (как делали)

1. `npm run build`, сервер на `:3000` раздаёт `dist/`, открыть `/?debug=1` → `window.__cityDebug = {scene, camera, renderer, world, remote, player, stylized, setQuality}`.
2. Для воспроизводимых кадров подмените `renderer.render`: перед каждым рендером выставляйте позицию камеры и `lookAt` из набора поз (старт, обзор сверху, фонтан вблизи, шесть зданий, газон, дорожка, скамьи, персонажи), после рендера сразу вызывайте `canvas.toDataURL()` и отправляйте в локальный приёмник (в этой работе — маленький Node-скрипт, пишущий PNG в `docs/graphics-overhaul/plaza-screenshots/`). Кадр нужно снимать **в том же вызове, что и render**, иначе буфер очистится.
3. В скрытой панели `requestAnimationFrame` замирает — вызывайте `world.update(dt, elapsed, player)` и `renderer.render` вручную, а `elapsed` задавайте сами (вода и ветер зависят от него).
4. Для «до» соберите коммит `HEAD` во временной папке (`git archive HEAD | tar -x -C <tmp>`, симлинк `node_modules`, `vite build`) и подмените `dist/` — рабочие файлы не затрагиваются; затем соберите новую версию.
5. Каждый раз после пересборки делайте жёсткую перезагрузку и проверяйте имя `main-*.js`, иначе увидите старый бандл.
6. Проверяйте: надписи читаются, нет мерцания (z-fighting) на брусчатке, тени на месте, пресеты Low/Medium/High различимы, персонажи в масштабе, переход в пожарную часть и обратно (E / L).
7. Персонажей без сервера можно показать так: `remote.join(id, name, {})`, `remote.snapshot([[id,x,0,z,ry,0]], t)`, `remote.update(t)`.

## 10. Тесты, которые нужно писать вместе с дизайном

* Геометрия: без индекса, атрибуты `position/normal/color`, `boundingBox` в габаритах, нет заметно подземных вершин, число вершин.
* План: коридоры к дверям, пересечения предметов, принадлежность газону, здания не накрыты деревьями.
* Декор: создаётся, реагирует на `setQuality`, `dispose` освобождает свои геометрии и не трогает общие.
* Чанк: загрузка и выгрузка с площадью, зданиями, дорожками → `scene.children.length === 0`, `pool.size === 0`.
* Запуск: `npm test`, `npm run build`, `npm run verify` (тесты + сервер + `/health`).
* Внешние URL: `grep -rE "https?://"` по новым файлам и `dist/assets/main-*.js` (скрипта `check:offline` пока нет).

## 11. Производительность: бюджеты и приёмы

* Меряйте `renderer.info.render.calls/triangles`, `memory.geometries/textures`. Время кадра на мощной машине вводит в заблуждение — ориентируйтесь на треугольники и draw calls.
* Ориентиры из этой работы (Средняя, с тенями): 66–97 calls и 256–391k треугольников; без теней — вдвое меньше треугольников.
* Приёмы экономии: плитки без боковых граней; не скруглять мелочь; низкие сегменты сфер у цветов (`w: 5, h: 4`); один материал на префаб; растения — `InstancedMesh`; декор с `drawRange`/`count` по качеству; общие геометрии через `sharedGeometry`.
* Тени дороже всего: если FPS недостаточен, сначала выключайте их на «Средней».

## 12. Частые ошибки

| Симптом | Причина | Решение |
|---|---|---|
| Геометрия «взрывается», ломаются габариты | правили общую `roundedBox` на месте | кит уже копирует; не мутируйте `userData.shared` |
| Мерцание плиток | два слоя на одной высоте | разнести на 0.01–0.02 или использовать подложку ниже |
| Вода/струи тусклые или слишком яркие | нет `tonemapping_fragment`/`colorspace_fragment` в шейдере | добавить оба include |
| Точки струй пропали | нет атрибута `position` или включён frustum culling | фиктивный `position`, `frustumCulled = false` |
| Растения качаются одинаково | фаза не из экземпляра | использовать `swayMaterial` (фаза из `instanceMatrix`) |
| Старая картинка после правок | кеш бандла | жёсткая перезагрузка, проверить хеш `main-*.js` |
| Декор не исчезает при выгрузке чанка | `dispose` не вызван | возвращайте `dispose` из `decorate`, тест `pool.size === 0` |
| Тест `min.y >= 0` падает на `-1e-10` | деталь стоит ровно на нуле | приподнять на 0.001–0.005 |
| Объекты внутри маршрутов | расстановка «на глаз» | считать от секторов и проверять `isClear` |
