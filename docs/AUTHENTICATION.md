# Настройка авторизации по паролю

Авторизация по имени и коду комнаты остаётся основным способом входа. Маршруты
`/api/register` и `/api/login` включаются только при `PASSWORD_AUTH=1`.

Для парольного входа задайте постоянный секрет `AUTH_PEPPER`, содержащий не
менее 32 случайных байт. Например, значение можно создать локально командой
`openssl rand -base64 32` и сохранить в окружении сервера, не в репозитории.
Без pepper сервер с включённым `PASSWORD_AUTH` завершит запуск с ошибкой.

Пароли хешируются Argon2id (19 MiB памяти, 2 прохода, параллелизм 1) после
HMAC-SHA-256 с pepper. PHC-строка Argon2id хранится в `users.pass_hash`, поле
`salt` для новых записей остаётся пустым: соль включена в PHC-строку.
Существующие scrypt-пароли переводятся на Argon2id при первом успешном входе.
Если `AUTH_PEPPER` потерян или заменён, пароли с прежним pepper больше нельзя
проверить; храните значение постоянно и отдельно от базы данных.

Сессии хранят HMAC-SHA-256 токена. Можно задать постоянный ключ
`AUTH_SESSION_SECRET` (не менее 32 случайных байт). Без него используется
случайный ключ на запуск сервера. Сервер принимает только сессии, выданные в
этом запуске, поэтому после перезапуска пользователям нужно войти снова. Другой
сервер с той же базой не отзывает действующие сессии; просроченные записи
удаляются при следующем входе.

Ограничитель `/api/login` и `/api/register` использует существующие настройки
`joinLimiter` и IP-адрес клиента. Неверные попытки и ошибки регистрации
учитываются, успешный вход или регистрация сбрасывают счётчик для IP.
