# Правила для ИИ-агентов (Claude Code, Codex)
- Проект: «Город профессий», работает офлайн на одном сервере в локальной сети.
- Язык: JavaScript (ES-модули), без TypeScript. Node.js LTS.
- Никаких внешних URL: ни CDN, ни шрифтов, ни аналитики. Только локальные ресурсы.
- Клиент: относительные адреса, WebSocket через location.host, токен в sessionStorage.
- Правь только свою папку (см. .github/CODEOWNERS). shared/ меняет только роль 2.
- Не используй git push --force, git reset --hard, git clean -fd, --no-verify.
- Коммиты малые, формат «область: что сделано».
- После задачи напиши и запусти проверку; перед коммитом запусти npm run verify.
- После проверки самостоятельно создавай нужные коммиты и отправляй обычным push; не запрашивай отдельное подтверждение. Запрещённые и необратимые Git-операции остаются запрещёнными.
- Не добавляй зависимости без согласования с тимлидом.
- Если нужна правка чужой папки или контракта, остановись и сообщи.

## Оркестрация Codex и Claude Code
- Codex координирует работу по умолчанию. Для сложных задач подготовь Claude Code готовый промпт с целью, ролью, актуальным контекстом, точными границами файлов, ограничениями, критериями приёмки и нужными проверками.
- Передавай Claude Code ограниченную самостоятельную задачу без пересекающихся правок. При параллельной работе используй отдельные worktree согласно Git-стратегии проекта.
- После работы Claude Code самостоятельно проверь его diff и Git-статус, соответствие роли и контрактам, выполни предусмотренные проверки; не принимай отчёт о тестах без фактических результатов.
- Простые задачи выполняй напрямую, если делегирование не улучшит качество или скорость. Общайся с человеком только по вопросам, которые действительно требуют его решения.

## Wiki (общая память Codex и Claude Code)
- Знания, решения и статус живут в GitHub Wiki; код и контракты (`shared/`) остаются в репозитории.
- Перед задачей: `npm run wiki:pull`, прочитай Home, Current Work, Agent Handoff и страницы своей подсистемы.
- После существенной задачи: обнови страницы, запиши в Development Log (формат: Задача, Цель, Контекст, Реализация, Решения, Изменённые компоненты, Проверки, Проблемы, Результат, Коммит, Следующие действия), затем `npm run wiki:push -- "wiki: что сделано"`.
- Клон Wiki лежит вне репозитория (`../<repo>.wiki`). Не коммить его внутрь, не используй `push --force`.
- Локальный коммит не считается публикацией; если Wiki ещё не создана на GitHub, сохрани страницы локально и попроси владельца создать первую страницу.
- Не пиши в Wiki секреты и непроверенные результаты: отделяй факты от планов. Подробности: страница Wiki Workflow.
- Чат только для вопросов к человеку и короткого итога (Выполнено, Проверено, Wiki, Блокеры).

## Control Center (админ-панель)
- Запуск: `ADMIN_PASSWORD=... npm start`, страница `/admin/` (доступ только с компьютера сервера, удалённый — `ADMIN_ALLOW_REMOTE=1`).
- Подсистема описана в `docs/admin-control-center/` (README, architecture, security, telemetry, world-editor, agents, testing, handoff).
- Для ручных проверок не используй настоящую `data/city.db`: запускай сервер через `startServer({ dbPath })` с временной базой.
