# Станция «Пожарный» — FIREFIGHTER_STATION_V1

Статус: вертикальный срез подключён к WebSocket и SQLite (ветка `codex/firefighter-db-progress`). Прогресс хранит и проверяет сервер; формат сообщений — `docs/PROJECT_CONTEXT.md`, раздел про `task_answer`/`task_state`.

## Цель и границы

Игрок проходит безопасную учебную смену под руководством Маруси Громовой: выслушивает инструктаж, надевает экипировку, выполняет условное упражнение по учебной мишени, переносит манекен в обозначенную зону и возвращается за итогом. Это игровая сценка, а не инструкция для реальных пожаров и не симуляция реального риска.

3D-страница `/firefighter-preview.html` показывает состояние, пришедшее с сервера (`task_state`), и отправляет только намерения (`task_answer`). Локального автомата в игровом режиме нет. Серверный идентификатор задания — `firefighter_station_v1`.

## Персонаж и структура контента

Предлагаемый формат контента — обычный ES-модуль/JSON-подобные данные в `content/firefighter/`; никакие сетевые или NPC API здесь не объявляются.

```js
{
  id: 'marusya_gromova',
  name: 'Маруся Громова',
  role: 'наставница учебной смены',
  greeting: 'Привет! Я Маруся. Сегодня потренируемся спокойно и по шагам.',
  briefing: 'Это учебный полигон. Сначала надень экипировку, затем работай с учебной мишенью. После этого перенеси манекен к зелёной отметке.',
  prompts: [
    { id: 'ask_equipment', text: 'Зачем нужна экипировка?' },
    { id: 'ask_teamwork', text: 'Почему важно действовать вместе?' },
    { id: 'ask_training', text: 'Зачем пожарные тренируются?' },
  ],
  fallback: 'Хороший вопрос. На настоящей службе этому учатся с наставником и по правилам команды.',
  debrief: 'Ты прошёл все этапы учебной смены: подготовился, потренировался и доставил манекен в безопасную зону. Спасибо за внимательность и командную работу!'
}
```

Реплики не должны советовать ребёнку тушить реальные пожары или входить в опасные помещения. Если разговорная модель появится позднее, она должна объяснять профессию и командную работу; игровой прогресс меняет только серверный обработчик задания.

### Безопасные темы для разговора

1. Для чего пожарным нужна защитная экипировка.
2. Почему перед упражнением важно выслушать инструктаж.
3. Как команда распределяет роли во время тренировки.
4. Зачем проверяют оборудование до начала упражнения.
5. Чем учебная мишень отличается от настоящего пожара.
6. Как сохранять спокойствие и слушать руководителя команды.
7. Почему после упражнения обсуждают, что получилось.
8. Какие качества помогают пожарным: внимательность, взаимопомощь, ответственность.
9. Какие средства связи помогают команде обмениваться информацией.
10. Как благодарить напарника за помощь и сообщать о затруднении.

## Сценарий и действия игрока

| Шаг | Объект / действие | Реплика или подсказка | Результат |
|---|---|---|---|
| 1. Начало | Подойти к Марусе, `E` / `start` | «Привет! Я Маруся. Готов пройти учебную смену?» | `briefing` |
| 2. Инструктаж | Подтвердить у Маруси, `accept_briefing` | Кратко объясняется безопасный порядок: экипировка → мишень → манекен → итог. | `equipping` |
| 3. Экипировка | Шкаф, `E` / `equip` | «Сначала подготовься. Подойди к шкафу экипировки.» | `fire_drill`, `equipped=true` |
| 4. Тренировка | Учебный рукав и мишень, `fire_hit` | «Направь струю на учебную мишень. Это игровое упражнение.» | Счётчик попаданий увеличивается до 18; затем `rescue`. |
| 5. Манекен | Манекен, `pickup_mannequin` | «Теперь перенеси учебный манекен к зелёной отметке.» | `carryingMannequin=true`, стадия `rescue`. |
| 6. Безопасная зона | Зелёная отметка, `deliver_mannequin` | «Отлично. Вернись к Марусе за итогом.» | `debrief`, `mannequinDelivered=true`. |
| 7. Итог | Маруся, `report` | Итоговая похвала за внимательность, подготовку и взаимопомощь. | `completed`, `done=true`. |

Ошибочные действия дают короткую контекстную подсказку и не меняют сохранённое состояние. Повтор уже засчитанного действия не добавляет прогресс. После `completed` повторные действия оставляют завершённый результат без изменений.

## Игровые состояния

`state.js` в клиентском превью — источник чистого автомата переходов: серверный адаптер повторно использует его функции, не поддерживая отдельную копию правил.

| Состояние | Видимая цель | Допустимое следующее действие |
|---|---|---|
| `not_started` | Поговорите с наставником у пожарной части | `start` у Маруси |
| `briefing` | Выслушайте инструктаж Маруси | `accept_briefing` у Маруси |
| `equipping` | Наденьте экипировку в шкафу | `equip` у шкафа |
| `fire_drill` | Потушите учебную мишень (`0/18` … `18/18`) | `fire_hit` у мишени |
| `rescue` | Доставьте манекен в безопасную зону | `pickup_mannequin` у манекена, затем `deliver_mannequin` у зоны |
| `debrief` | Вернитесь к Марусе за итогом тренировки | `report` у Маруси |
| `completed` | Учебная смена завершена | Нет переходов; можно только показывать сохранённый итог |

### Таблица переходов

| Текущее состояние | Действие | Условие / объект | Новое состояние и изменение |
|---|---|---|---|
| `not_started` | `start` | рядом с Марусей | `briefing` |
| `briefing` | `accept_briefing` | рядом с Марусей | `equipping` |
| `equipping` | `equip` | рядом со шкафом | `fire_drill`, экипировка надета |
| `fire_drill` | `fire_hit` | у учебного рукава, направив его на мишень | +1 попадание; на 18-м — `rescue` |
| `rescue` | `pickup_mannequin` | у манекена, игрок ещё не несёт его | `carryingMannequin=true` |
| `rescue` | `deliver_mannequin` | у безопасной зоны, игрок несёт манекен | `debrief`, манекен доставлен |
| `debrief` | `report` | рядом с Марусей, манекен доставлен | `completed`, серверный `done=true` |
| любое иное сочетание | любое действие | неверный порядок, нет позиции, неверный объект | состояние и запись SQLite не меняются |
| `completed` | любое действие | повторный запрос | состояние и запись SQLite не меняются |

## Интерактивные объекты и пространственная проверка

Ключи точек: `npc`, `locker`, `hose`, `target`, `mannequin`, `safe_zone`. Каноничные координаты — `client/stations/firefighter/layout.js`: точки заданы на полигоне (локальные координаты), мировые получаются сдвигом `world = local + FIRE_ORIGIN` (без поворота и масштаба); `FIRE_ORIGIN` подобран так, что точка появления нового игрока `SPAWN` совпадает со стартом полигона `(0, 13.25)`. Сцена, клиентский сетевой слой и сервер читают одни и те же значения; преобразование и «вся станция в соседних чанках от спавна» проверяет `layout.test.js`.

Сервер сопоставляет действие с точкой и сравнивает **серверную** позицию игрока с точкой по расстоянию на земле (X, Z) плюс допуск по высоте 4 м. Радиус на сервере равен клиентскому плюс 1 м (позиция отстаёт на кадр-другой). Клиентские радиусы: Маруся 2.8 м, шкаф 2.5 м, манекен 2.4 м, безопасная зона 2.6 м.

`fire_hit` дополнительно: игрок не дальше 7 м от стойки рукава (`HOSE_REACH`, +1 м допуска), смотрит на мишень в пределах 0.45 рад (угол `ry` из последнего принятого `pos`; в игре персонаж поворачивается туда же, куда прицел) и не чаще раза в 120 мс. Состояние и порядок этапов проверяет автомат `state.js`: сначала порядок и повтор, затем позиция, затем частота. Любое отклонение не меняет состояние и не пишет в SQLite.

Ограничение: `ry` присылает клиент (сервер проверяет скорость перемещения, но не скорость поворота), поэтому направление — проверка «разумности», а не защита от модифицированного клиента. Для этого нужен серверный aim.

## Сохранение

- Ключ — пара авторизованный `userId` + `firefighter_station_v1` в существующей `task_progress`.
- Используются только `getTaskProgress(userId, taskId)` и `saveTaskProgress(userId, taskId, { state, done }, now)`; запись из базы, не прошедшая проверку формата, игнорируется (задание начинается заново).
- Состояние для записи строится переходом автомата на сервере; `done` вычисляется как `stage === 'completed'`.
- Незавершённые допустимые переходы записываются, после пересоздания обработчика читается последний этап; два пользователя имеют отдельные строки.
- Не добавляются таблицы, колонки или отдельные системы прогресса.

## Интерфейс станции

- Панель наставника: имя/портрет, реплика, варианты безопасных вопросов и кнопка продолжения инструктажа.
- Панель цели: одна короткая цель за раз, счётчик `0/18` для учебной мишени и подтверждение каждого этапа только после ответа сервера.
- Контекстный prompt `E` появляется только у доступного объекта; недоступный по порядку объект показывает пояснение без изменения состояния.
- Во время отправки действия UI показывает ожидание; при сетевой ошибке не отображает неподтверждённый успех.
- После восстановления серверного `task_state` UI перерисовывается из сохранённого состояния; локальное состояние 3D-превью остаётся отдельным демонстрационным режимом.
- Управление закрытием диалога не сбрасывает зафиксированный сервером прогресс.

## Сетевой шов

`task_answer {taskId, payload: {action}}` → `server/net/game.js` вызывает `app.taskHandlers.handle(userId, taskId, payload, {position, yaw})` с `userId` соединения и последней принятой позицией → ответ `task_state`. После `welcome` сервер присылает `task_state` с сохранённым прогрессом, поэтому перезагрузка страницы, вход с другого компьютера и переподключение продолжают с того же места. При сбое записи в базу клиент получает `error: 'storage'` и прежнее состояние. Не подключено: диалоги Маруси через `npc_talk` (S3).
